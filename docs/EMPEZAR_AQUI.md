# Empezar aquí

Esta guía es para quien quiere mirar el proyecto o proponer algo sin programar. No necesitas instalar nada.

## Qué es esto

Esta página de GitHub es el **repositorio** (o "repo") de EcoWaste: la carpeta compartida donde vive todo el sitio web.
Guarda cada versión de cada archivo, así que nada se pierde y siempre se puede volver atrás.
Nadie edita la versión publicada directamente: cada cambio se propone aparte y se revisa antes de entrar.
Cada cambio propuesto genera una **vista previa**, una copia del sitio con el cambio aplicado que puedes abrir en tu teléfono.
Solo la delegación Operaciones y recursos edita el repo. El resto del grupo aporta datos y textos por Drive y WhatsApp.

## Cómo ver el sitio

- **Sitio publicado:** `[PENDIENTE]`. Cuando exista, el enlace va a estar aquí y al principio del [README](../README.md).
- **Vista previa de un cambio:** Operaciones comparte el enlace por WhatsApp. También puedes abrir la pestaña [Pull requests](https://github.com/nemura0/ecowaste/pulls), entrar al cambio y buscar el comentario automático que trae el enlace.

## Cómo proponer algo sin programar

| Quieres… | Haz esto |
|---|---|
| Agregar o corregir un punto del mapa | Llena una fila en la planilla de puntos de Drive. Pídele el enlace a Operaciones. Sin fuente, el punto no se puede cargar: revisa en [DATOS.md](DATOS.md) qué cuenta como fuente |
| Entregar un texto (qué reciclar, acerca del proyecto) | Súbelo a la carpeta de Drive del grupo con su fuente y avísale a Operaciones |
| Avisar de un error o proponer una idea | Escríbele a Operaciones por WhatsApp. Si tienes cuenta de GitHub, puedes abrir una [issue](https://github.com/nemura0/ecowaste/issues/new/choose) |
| Opinar sobre un cambio | Abre la vista previa y responde en el WhatsApp del grupo |

## Glosario

| Palabra | Qué significa |
|---|---|
| Repositorio (repo) | La carpeta compartida del proyecto, con su historial completo |
| Commit | Un cambio guardado, con un mensaje que dice qué se hizo |
| Rama | Una copia de trabajo donde alguien prepara cambios sin tocar la versión publicada |
| Pull request (PR) | La propuesta de llevar los cambios de una rama a la versión publicada. Ahí se conversa y se revisa |
| Vista previa | Una copia del sitio con los cambios de un pull request, para mirarla antes de aprobar |
| Verificación | La revisión automática de cada pull request. Muestra un visto verde o una cruz roja |
| Merge | Aceptar un pull request: los cambios pasan a la versión publicada |
| Issue | Una tarea o un problema anotado en GitHub, para que alguien lo tome |

## Qué no se sube nunca

- Claves, contraseñas ni archivos `.env`.
- Nombres, correos o teléfonos de compañeros, ni la nómina del grupo.
- La ficha del proyecto, respuestas de encuestas ni otros archivos de contexto del grupo.
- Fotos en las que se reconozca a alguien.
- El logo o la marca de la universidad.

Si ves algo de esto en el repo, avísale de inmediato a Operaciones.

## Práctica: tu primer pull request desde la web

Esta sección es para Operaciones y sirve para probar que la vista previa funciona con cambios de cualquier persona. Se hace solo una vez.

1. En GitHub, entra a **Settings → Emails** y activa **"Keep my email addresses private"**. Así tu correo no queda público en el historial.
2. Abre este archivo en GitHub (`docs/EMPEZAR_AQUI.md`) y aprieta el ícono del lápiz (**Edit this file**).
3. En la línea de abajo, cambia `pendiente` por `hecha` y agrega la fecha.
4. Aprieta **Commit changes…**, elige **"Create a new branch for this commit and start a pull request"** y luego **Propose changes**.
5. Aprieta **Create pull request**. En unos minutos debería aparecer un comentario con la vista previa.

Estado de la práctica: pendiente.
